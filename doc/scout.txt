*scout.txt*  Branch review mode for Neovim

==============================================================================
INTRODUCTION                                                    *scout*

Scout is a structured branch review tool for Neovim. It shows changed files
in a side panel, lets you open/diff each one, tracks which files you've
reviewed, and persists that progress across editor restarts.

Requires Neovim 0.10+ and Git. Run `:checkhealth scout` to verify Git and
optional integrations.

==============================================================================
INSTALLATION                                                    *scout-install*

Via lazy.nvim: >lua
  {
    url = "https://git.bobparsons.dev/deadstyle/scout.nvim",
    dependencies = {
      "lewis6991/gitsigns.nvim",        -- optional: hunk gutters
      "sindrets/diffview.nvim",         -- optional: side-by-side diff
      "nvim-telescope/telescope.nvim",  -- optional: branch picker
    },
    opts = {},
  }
<

==============================================================================
SETUP                                                           *scout-setup*

Call `require("scout").setup(opts)` with an optional options table. All keys
are optional — omitted keys keep their defaults.

Default options: >lua
  require("scout").setup({
    keys = {
      start      = "<leader>rv",   -- start review (auto-detect base branch)
      start_pick = "<leader>rV",   -- start review (picker for base branch)
      quit       = "<leader>rq",   -- exit review mode
    },
    panel = {
      width    = 45,          -- panel width in columns
      position = "topleft",   -- "topleft" or "botright"
    },
    integrations = {
      gitsigns  = true,  -- change gitsigns base to show diffs from merge-base
      diffview  = true,  -- open diffview.nvim on `d` in panel
      telescope = true,  -- use telescope for branch picker
    },
    exclude = {},        -- glob patterns; matching files are hidden from panel
  })
<

To disable a keymap, set it to `false`: >lua
  opts = { keys = { start_pick = false } }
<

                                                                *scout-exclude*
`exclude` ~
  A list of glob patterns. Any file whose repo-relative path matches a pattern
  is hidden from the review panel. Globs use shell-style `*` (which matches
  across `/`), compiled via `glob2regpat`. Example: >lua
    require("scout").setup({ exclude = { "*_test.go", "vendor/*" } })
<
  Press `x` in the panel to toggle visibility of excluded files.

==============================================================================
COMMANDS                                                        *scout-commands*

`:Scout [base]`                                                 *:Scout*
  Start a review session in the current buffer's repository, falling back to
  the current working directory. Optionally pass a base branch/ref. If
  omitted, scout auto-detects the repo default branch (the origin remote's
  HEAD, then origin/main, origin/master, or a local main/master).

  If a session is already active, :Scout reopens (or focuses) its panel
  instead of starting over — handy after closing the panel with `q`.
  Passing a different base while active is refused; quit first.

`:ScoutQuit`                                                    *:ScoutQuit*
  Exit the current review session, close its Diffview and panel, and restore
  gitsigns.

`:ScoutDiffClose`                                          *:ScoutDiffClose*
  Close the Diffview opened by Scout and return focus to the Scout panel.

`:ScoutRefresh`                                              *:ScoutRefresh*
  Re-scan the changed files for the active session and update the panel,
  preserving reviewed state for files whose content is unchanged. Useful
  after a new commit, amend, or rebase. Scout also refreshes automatically
  when focus returns to Neovim and HEAD has moved.

==============================================================================
PANEL KEYMAPS                                                   *scout-panel*

These keymaps are active only inside the Scout panel buffer:

  <CR>   Open the file under cursor in the main editing window. For a deleted
         file (status D) there is no working-tree copy, so <CR> opens its diff.
  d      Open a side-by-side diff via diffview.nvim
  r      Toggle the file's reviewed status (✓ / unreviewed)
  x      Toggle visibility of excluded files (show/hide files matching the
         `exclude` patterns)
  q      Close the panel (does not end the session). Re-run :Scout or the
         start keymap to reopen it for the same session.
  ?      Show this keymap reference as a notification

In a Diffview opened by Scout, `q` closes the Diffview and returns to the Scout
panel. `:ScoutDiffClose` provides the same behavior.

==============================================================================
FEATURES                                                        *scout-features*

File display ~
  The panel lists every file that differs from the merge-base, including
  uncommitted working-tree changes, so the panel and the gitsigns gutters
  always agree on what changed. Each panel line shows the status letter and
  path, plus right-aligned
  +added/-deleted line counts. The status letter is color-coded: A green,
  M/R/T orange, D red. Counts are omitted for binary files. The highlight
  groups (`ScoutStatusAdded`, `ScoutStatusModified`, `ScoutStatusDeleted`,
  `ScoutStatusRenamed`, `ScoutStatusTypeChanged`, `ScoutAdded`, `ScoutDeleted`)
  link to the standard diff groups by default and can be overridden.

Auto-preview ~
  Moving the cursor over a file in the panel automatically opens it in the
  main window and, when gitsigns integration is enabled, jumps to the first
  changed hunk (debounced 150ms). Focus stays in the panel. Deleted files are
  skipped (use <CR> for their diff).

Persistence ~
  Reviewed-file state is saved to:
    `$XDG_STATE_HOME/nvim/scout/{sha256(key)}.json`

  Reviewed marks persist across Neovim restarts and across new commits on the
  branch. A file is automatically dropped from the reviewed set when its
  content changes — whether via a new commit or an in-progress edit saved to
  disk — so changed content is never silently treated as already reviewed.

Optional integrations ~
  All three optional integrations (gitsigns, diffview, telescope) degrade
  gracefully if the plugin is not installed — scout warns once and continues.
